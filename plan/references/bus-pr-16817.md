## What PR #16817 delivers

A **prepaid wallet billing ledger** for API clients:

- Filter form (date range ≤31 days, direction, transaction type, PNR/mobile)
- **Generate** → serverSide DataTables page
- **KPI summary row** refreshed from JSON `summary` on each fetch
- **18-column ledger table** with txn type pills, money columns, hover states
- Active filter chips after successful fetch
- Export CSV (server) + print PDF (current page rows only)
- Table loading overlay during AJAX

## Query optimization (host SQL — reference only)

Patterns to document in [query-optimization.md](../critical-paths/query-optimization.md):

1. Single aggregate query: `COUNT + SUM(credit) + SUM(debit)`
2. True SQL pagination: `skip($start)->take($length)`
3. Conditional `recordsTotal` only when search active
4. Batch order hydration: one query for all `reference_id`s on page
5. PNR filter: pre-resolve to ID list, then `whereIn`
6. Export: one query for full filtered set (small date window)

## ReportKit adaptation — JSON browse (no re-query)

For **`hybrid-browse`** preset, table UX follows billing design but data source differs:

| Billing (bus) | ReportKit hybrid-browse |
|---------------|-------------------------|
| Each page = SQL query | Each page = `PseudoPaginator::slice()` on prepared JSON |
| Prepare N/A | Week-chunk prepare first |
| `summary` from SQL aggregates | `summary` from in-memory `SummaryBuilder` |
| Export CSV hits DB | Export from prepared store |

**API:** `GET /report/data-browse?draw=1&start=0&length=25&search=…`  
Server reads prepared rows from session/cache — **zero domain SQL**.
