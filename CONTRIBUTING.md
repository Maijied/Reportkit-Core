# Contributing to ReportKit

Thank you for your interest in ReportKit. This project is developed by
**Lorapok Labs** — **Mohammad Maizied Hasan Majumder**.

## Before you start

1. Read the [LICENSE](./LICENSE) — ReportKit is **free to use and modify**, but
   **not free to sell** or offer as a paid product without a commercial license
   from Lorapok Labs.
2. Read the [Code of Conduct](./CODE_OF_CONDUCT.md).
3. Pick a category in [GitHub Discussions](https://github.com/Maijied/Reportkit-Core/discussions):

   | Category | Use for |
   |----------|---------|
   | [General](https://github.com/Maijied/Reportkit-Core/discussions/categories/general) | Open questions and conversation |
   | [Q&A](https://github.com/Maijied/Reportkit-Core/discussions/categories/q-a) | Installation and integration help |
   | [Ideas](https://github.com/Maijied/Reportkit-Core/discussions/categories/ideas) | Feature proposals |
   | [Show and tell](https://github.com/Maijied/Reportkit-Core/discussions/categories/show-and-tell) | Share what you built |

   Prefer [Discussions](https://github.com/Maijied/Reportkit-Core/discussions) over Issues for questions.

## Development

- Change only the package directory relevant to your work when possible.
- Run package tests before submitting a pull request.
- Keep provenance and scale-honesty labels intact in demo and docs.
- Do **not** push package source to Shohoz Azure remotes.

## Pull requests

1. Fork and branch from `main`.
2. Write a clear description of the change and why it is needed.
3. Confirm you have the right to contribute the code and that it complies with
   the [LICENSE](./LICENSE).
4. Link related Discussions or issues when applicable.

## Security

Do not open public issues for security vulnerabilities. See [SECURITY.md](./SECURITY.md).
